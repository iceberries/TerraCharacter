# Terra Character：人物与世界分离设计及实施规划

## 目标与本次范围

目标流程：主菜单 → 人物列表 → 创建人物／捏人／人物难度 → 选择人物 → 自己的世界／他人的世界 → 世界列表／服务器列表 → 创建世界／世界难度 → 使用选定人物进入选定世界。

一个账号可以拥有多个人物，同一人物可以进入多个兼容世界，同一世界可以由不同人物进入。账号 UUID 仍用于 Minecraft 登录、权限和联网身份，人物 UUID 用于人物资产，世界 UUID 用于世界身份；三者不互相替代。名称只是显示文字，重名合法，不用名称拼接存储路径。

用户已确认“任务难度”指“人物难度”。人物难度管理死亡惩罚，世界难度管理战斗规则。旅行人物只能进入旅行世界，其余人物可进入原版和平、简单、普通、困难世界；汇流兼容模块扩展经典、专家、大师战斗模式。第二阶段提供服务端授权的旅行研究、复制、飞行、无敌及时间／天气控制。

第二阶段已实现实际单人流程及双方安装模组的多人独立人物，兼容模块接入汇流资产和规则；具体验证范围见 [验证记录](VALIDATION.md)。第三阶段继续打磨 UI、资源扩展与诊断体验。

安装关系（2026-10-13 更新）：仅分发 TerraCharacter。原 TerraCharacterConfluence 的代码、资源、Mixin 和测试已合并到其中；汇流是可选运行依赖。兼容入口通过 ModList 检测并延迟加载；事件监听器显式按安装状态与物理端注册，Mixin 插件依据加载器的模组列表启用。原有 terra_character_confluence 命名空间保留为存档标识，避免已有资产和世界配置失效。下文旧阶段的双模块构建记录属于历史方案，当前构建与安装说明见 CONFLUENCE.md。

## 数据归属

| 所有权 | 代表数据 | 跨世界行为 |
| --- | --- | --- |
| 账号 | 登录 UUID、权限、服务器白名单与封禁 | 不随人物替换 |
| 人物 | 人物 UUID、名字、外观、难度、硬核死亡状态、物品栏、装备、饰品、扩展背包、猪猪储蓄罐、保险箱 | 随人物移动 |
| 人物 | 永久生命／魔力提升、已使用永久道具、渔夫任务累计完成次数 | 随人物移动；属性从基础与永久数据重新计算 |
| 人物状态 | 当前生命、当前魔力、经验、明确允许转移的效果 | 由白名单适配器处理，死亡后的恢复规则单独校验 |
| 人物＋世界 | 所在维度、位置、床与重生点、探索／进度记录、当天渔夫任务完成标记 | 按 `(characterId, worldId)` 隔离 |
| 世界 | 种子、预设、邪恶类型、基础难度、特殊种子、Boss／事件进度、肉后转化、NPC 房屋、全局任务鱼、天气和时间 | 留在世界 |
| 会话／派生 | PvP／队伍策略、菜单容器、交易对象、临时战斗状态、敌怪旗帜范围缓存、属性修饰符缓存 | 进入时初始化或重算 |

`PlayerSpecialData` 混合多种所有权，不能整体拷贝：`AnglerQuestCount` 归人物，`CompletedAnglerQuestDay` 必须绑定世界，当前任务鱼需重新验证本世界的 `AnglerData`，队伍／PvP／旗帜缓存按会话策略处理。否则两个世界日期相同会错误地阻止接任务。

原版 player NBT 也不能整体复制：账号 UUID、维度、坐标、床、传送门状态和世界引用不得进入可跨世界快照。`copyOnDeath` 只处理同一人物的实体重建，不能代替人物选择与跨世界加载。

## 模块与 API

依赖方向为：

```text
TerraCharacter → Minecraft / NeoForge
TerraCharacterConfluence → TerraCharacter
                        → ConfluenceOtherworld → 汇流现有组件
```

当前 Gradle 仅以 compileOnly 引用汇流／前置供兼容代码编译，单独运行时不放入 runtimeClasspath。-PwithConfluence=true 仅为开发运行添加汇流及其前置；发行 JAR 不嵌入它们。元数据声明汇流为可选并在其后加载，不再分发独立兼容模组。

第二阶段在核心内实现原版 `CharacterDataAdapter`，在兼容模块内实现汇流／饰品适配器，通过核心提供的注册入口组装。核心业务只使用接口；汇流本体无需认识此接口，兼容模块缺失时不会加载任何汇流适配类。

| 层 | 框架契约 | 第二阶段实现 |
| --- | --- | --- |
| `api/model` | 不可变人物、外观、原版世界配置和通用扩展字段；名字、资源 ID、RGB 校验 | 版本化编码、默认体型／发型与颜色、旅行状态 |
| `api/repository` | 按 UUID 查找、列举和只新增契约，I/O 失败显式传播 | 原子文件读写、隔离损坏条目、索引、备份、锁 |
| `service` | 注入仓储，创建人物元数据／世界元数据，校验选择 | 编辑、删除、导入、保存冲突处理 |
| `api/session` | 拒绝死亡人物、旅行兼容性校验 | 会话生命周期、持有锁、本地与多人身份绑定及客户端便携数据导入 |
| `api/integration` | 分人物／人物世界的数据适配 SPI，capture／restore／initialize | 注册、迁移、回滚、完整性检查与同步 |
| 客户端 | 自有默认样式、可选兼容入口 | 人物列表、捏人预览、世界列表、错误与确认页面 |
| TerraCharacterConfluence | 独立入口、双前置、汇流世界选项元数据转换 | 汇流数据适配器、特殊种子／难度映射、掉钱和复活兼容 |

核心 `WorldDifficulty` 为原版和平、简单、普通、困难，加上独立的旅行模式；旅行不能简单等同于和平或创造。`WorldSettings` 保存原始种子、预设、基础难度和不可变的 `Map<String, String>` 扩展字段，扩展键必须带命名空间。

邪恶类型与经典／专家／大师选项由兼容模块的 `ConfluenceWorldOptions` 管理，以 `terra_character_confluence:world_difficulty` 和 `terra_character_confluence:evil` 扩展键保存。经典／专家／大师分别使用现有 0.75／1.5／2.25 有效难度；传奇继续由特殊种子派生。未知扩展保留，加载协调器要求对应的选项提供者注册并验证，配置冲突拒绝进入。已有普通世界没有这些扩展时继续使用其原有难度与世界标志。

核心独立提供原版背包／装备、经验、位置、死亡与重生处理，不调用汇流工具类。软核保留物品和经验；中核走原版掉落；硬核按人物永久死亡；汇流货币及其难度比例只由兼容模块处理。核心 UI 使用自有默认样式，汇流风格留待第三阶段打磨。

外观以资源 ID 表示体型和发型，命名颜色通道用 RGB。第二阶段内置标准／纤细体型、短发／长发／发冠，以及六种颜色通道，生成与预览一致的本地皮肤；未知样式回退默认外观，原始元数据保留。激活人物会话时本地玩家使用人物皮肤，否则使用原版账号皮肤。可由资源包扩展的外观注册表留待第三阶段。

## 第二阶段存储与会话实现

人物以单个 `character.nbt` 作为权威包，包含版本、revision、人物元数据、按适配器分组的便携资产、按世界 UUID 分组的局部状态和旅行研究。将原设计中的 profile／state 两文件以及人物世界局部状态合并到同一个原子提交，避免跨文件只提交一半。世界目录另存身份、局部恢复镜像及各人物的统计／进度 JSON。

写入使用强制刷盘的临时 NBT、读回校验、上一版备份和原子替换；不支持原子替换的文件系统直接报错。人物 UUID 文件锁与 revision 检查阻止重复登录和过期编辑。删除是可恢复归档；损坏条目独立列出并提供备份恢复。未来版本和未知适配器不降级覆盖。

进入现有世界前，离线取得世界锁，建立人物包与完整世界的共同检查点，然后写入两侧会话标记。现有世界的检查点 I/O 在后台执行，界面显示等待；世界载入成功前不开放交互。进入后在服务器线程初始化全部已注册适配器，再按便携／局部分组恢复；账号 UUID、整份原版 Attributes 和世界进度不会写入人物便携包。永久属性与饰品能力从恢复的资产重新计算。

正常退出时先提交人物、保存世界，再清除会话标记和检查点。进程被杀或保存失败时，阻止该人物和该世界继续游玩，用户从人物菜单确认恢复；恢复成对回到进入前，保留中断世界副本，不单独回退背包。硬核墓碑在死亡时先独立提交，恢复检查点或备份也不能撤销。该保守协议牺牲中断会话内进度来避免人物和世界单边回退导致复制物品；后续可优化检查点大小和增量恢复。

旧人物导入显式选择单人所有者或 `playerdata` 账号文件，要求来源已保存为当前 Minecraft 数据版本。备份来源与统计／进度，拒绝未知附件，按适配器白名单拆分，再用持久导入台账与暂存包保证重试幂等。原账号文件保持不变。原版世界硬核只能导入硬核人物，再为人物创建普通世界；世界不被静默改为非硬核。

世界身份只持久生成一次，改名不改变 UUID；索引检测复制世界的重复 UUID，通过明确操作为副本分配新身份。原版创建界面继续负责名称、种子、预设与实际生成，额外界面提供人物与兼容世界选项。缺失选项提供者、缺失物品／效果、未知附件或不兼容人物组合均拒绝有损恢复。

多人采用配置任务＋会话协调器，核心协议版本 5。一次性 nonce 绑定连接，客户端锁住本机人物并上传便携包（仅 `Profile`、`Adapters`、`Journey`），服务器验证身份、适配器作用域、版本与资源引用后，在原版玩家载入前按 `(authenticatedAccountId, characterId)` 绑定人物。**入服便携数据以客户端为准**，服务端旧镜像即使 revision 更大也被替换；世界局部状态、统计和成就仍由对应世界保存。客户端与镜像分别维护 revision，不能跨存储比较。服务端旧死亡镜像可以被本机状态替换，本机硬核墓碑仍阻止本机复活。

服务器在保存和便携状态变化时向连接回写人物，客户端验证 nonce、人物 ID、服务端序号及本地 revision，原子合并便携部分并保留本地 `Worlds`。每 100 tick 检查便携数据变化，原有 1200 tick 保存继续有效。正常退出及关闭窗口执行“请求最终保存 → 接收最终快照 → 本机提交 → 断开”；超时可重试，写盘失败显示错误并断开。非正常断线保留最近成功回写的本机快照，下次加入依然以该本机快照为准。配置中断、断线或退出释放本机和服务器人物锁，原版最终保存之后才释放服务端锁。

传输使用压缩 NBT 有界分片，24 KiB／片、压缩总量 8 MiB、解压配额 32 MiB；每连接独立组装，拒绝乱序、重复、超限及错误结构。人物状态只发给本人，外观按账号实体 UUID 广播给其他玩家，账号认证身份始终不变。

开放局域网前提交离线人物与世界，永久标记共享并移除离线共同检查点。共享世界禁止整世界回滚；旧检查点恢复遇到共享标记仅清理标记及检查点。专用服务器也使用共享标记与独立服务端人物目录。每份人物包原子提交，整个多人世界使用 Minecraft 常规保存粒度；不声称跨全部玩家和区块的事务一致性。

旅行能力请求只发送有限动作，服务器复查当前人物身份、旅行难度、研究进度与背包容量，不接受客户端物品 NBT。修改全局时间或天气要求管理员或本地所有者身份。服务端人物管理界面仍为后续扩展。

| 2.6 迁移与完整闭环 | 旧存档显式导入，退出／断线／关服保存，崩溃恢复；客户端便携人物联机协议作为独立扩展 | 导入可恢复且幂等；缺失模组无静默数据丢失；单人恢复成对回退，重复登录拒绝并发操作；缺失适配器时拒绝载入人物包 |
| 2.7 统一入口与多人独立人物 | 先选人物再选择世界／服务器；配置挑战、账号＋人物服务端存档、外观广播、共享世界策略 | 双客户端 A／B／A 重连不串背包或统计；本机便携数据优先，在线死亡及权限由服务器执行；双方看见绘制外观；共享后不能用离线检查点回滚其他玩家进度 |

2.1～2.3 形成可创建和选择的界面闭环，2.4～2.6 才形成可实际游玩的数据闭环；不能把仅有选择 UI 的版本宣称为人物世界分离完成。

2.1～2.6 的单人功能均已落地；后续新增统一“开始游戏”入口和多人便携人物协议，覆盖账号＋人物隔离、配置阶段绑定、外观广播与共享世界保存策略。缺失提供者／未来版本采用拒绝进入的保护策略。自动化及实际客户端结果分别记录，未实测的安装组合与断电场景不计为通过。

### 第三阶段：打磨细节

完善独立 UI 默认风格及可选汇流风格，补齐中英文、键盘焦点、窄窗口和 GUI 缩放；增加人物预览、世界缩略图、最近游玩与排序筛选；删除、覆盖和导入提供清晰确认与恢复路径。

用户指定捏人参考“凡家物语”（MCA／MCA Reborn）。参考其 [发型／服装独立图层与实时着色](https://github.com/Luke100000/minecraft-comes-alive/wiki/Skin-Editor) 和 [外观资源分类](https://github.com/Luke100000/minecraft-comes-alive/wiki/Custom-Skin-Textures)，第三阶段将当前的基础体型、发型及 RGB 编辑升级为：

- 分身体、发型、面部、服装的部件选择，缩略图网格与全身／头部预览。
- 预设肤色和配色、可视颜色选择器；保留高级 RGB 输入。
- 基础身体、发型、眼睛、服装分层组合；发型可染色，图层资源可由资源包扩展。
- 预览旋转与缩放、整个人物／当前部位随机、重置与取消恢复。

这些是后续外观扩展计划，当前版本使用基础生成皮肤，并已补充下述像素绘制工具。MCA 作为交互与数据组织参考，TerraCharacter 不增加 MCA 前置，也不直接使用其素材或实现。外观资源的缺失回退仍须保留原始人物元数据。

#### 皮肤绘制补充

- `CharacterAppearance.paint` 为不可变 `SkinPaint`：64×64 ARGB 像素覆盖，0 表示使用生成像素，非零必须完全不透明。基础层生成不透明，外层生成透明，因而擦除分别还原原色和透明。颜色通道和绘制内容独立保留。
- `SkinLayout` 定义现代皮肤的六部位、六个面、基础／外层 UV，处理纤细手臂的 3 像素宽度与独立左肢。渲染只采样有效 UV，空白 UV 保持透明；笔刷裁切到当前面。
- `SkinCanvas` 管理界面草稿，拖动插值补齐笔画、32 步撤销／重做、按面还原。取消不改人物；应用只更新父编辑器草稿，最终人物保存沿用原有锁、原子写入和备份。
- 皮肤编辑器复用单张动态纹理，脏帧上传；关闭释放纹理。实时模型与实际玩家均显示外层，编辑器额外允许隐藏外层。人物状态按收到的新包缓存，避免每帧反复解码像素数组。
- 人物 NBT `Appearance.Paint` 为可选且严格校验的 4096 元素 int array；原有格式版本兼容缺省字段。未知类型、尺寸错误或非不透明的非零像素拒绝载入。状态同步直接携带人物外观，无外部文件引用或汇流依赖。

当前范围为像素绘制和擦除；半透明画笔、PNG 导入导出、更多部件资源仍可独立扩展。

优化列表缓存和大存档读写，完善错误提示、备份管理和诊断日志。回归特殊种子、旅行兼容、饰品模组、渔夫任务、Boss 进度、复活倒计时和旧存档；覆盖磁盘满、损坏 NBT、未来版本、缺失资源、保存中退出及应用中断。

最终验收：人物 A／B 与世界 X／Y 的交叉矩阵、重启保存、全部人物难度与世界难度、首次进入与再次进入、普通旧存档和明确导入流程都通过实际游戏验证。分别验证仅核心、核心＋汇流、核心＋汇流＋兼容模块三种安装组合，以及兼容模块缺少前置和卸载扩展后的数据保护，再认定完整功能完成。

## 第二阶段实现索引

- `storage`：NBT 编码、原子写入、人物仓储、世界身份、共同检查点恢复。
- `service`：世界索引／副本识别、来源选择／备份／导入台账。
- `client`：人物列表、回收站、编辑与实时模型、世界选择／原版创建衔接、旅行和硬核死亡界面。
- `runtime`：本地与多人服务器身份绑定、初始化／恢复／采集／保存、死亡惩罚、旅行授权。
- `network`：服务端人物状态同步与有限旅行动作。
- `mixin`：原版人物文件保存隔离、统计路径、掉落／复活、世界创建、皮肤／HUD 与局域网入口。
- 兼容模块：汇流／Curios 适配器、渔夫字段拆分、选项校验、特殊种子与有效难度、扣钱／软核提示／HUD 接点。
- `src/smokeTest`：仅开发运行时加载的真实客户端交叉测试，不进入发行 JAR；最终结果以实际测试报告为准。

### 第三阶段：人物卡片与原生世界界面

人物选择使用分页平铺的 3D 卡片；单击选择，同一卡片 250 ms 内再次单击确认，键盘激活只选择，开始游戏按钮保留。预览使用独立、无连接且不 tick 的客户端人物实体，只读人物存档的原版背包／盔甲／双手物品，兼容模块补充虚荣盔甲、染色和 Curios（含外观槽、显示开关），复用原生 PlayerRenderer。预览不会替换 Minecraft.level/player 或写回人物数据。

自己的世界入口使用原版 SelectWorldScreen，不替换原版列表或 Confluence 的图标增强。原版世界条目的双击与进入按钮统一经过 WorldOpenFlows 边界，在校验人物／世界配对并建立检查点后继续原版打开流程；失败时清理待进入会话。复制世界身份修复与旧人物导入保留在独立“世界数据工具”入口。
